# Backend

Небольшой самостоятельный API на Express + TypeScript + MongoDB. Angular остаётся
в корневом `src/`; его SSR-сервер `src/server.ts` обслуживает сайт и не является этим API.
У бэкенда собственные зависимости, конфигурация TypeScript и порт (3000).

## Первый запуск

Требуются Node.js 24, pnpm 11 и MongoDB. Из корня репозитория:

```bash
pnpm install
cp backend/.env.example backend/.env
# Локальная MongoDB (Docker Desktop должен быть запущен):
docker compose -f backend/compose.yaml up -d --wait
pnpm backend:seed
pnpm backend:dev
```

Вместо Docker можно указать URI MongoDB Atlas в `backend/.env`.
`MONGODB_DB` задаёт базу. Строку подключения не коммитить.
Docker-конфигурация предназначена только для локальной разработки: база без
авторизации доступна на 127.0.0.1, данные сохраняются в Docker volume.

Seed переносит текущие демонстрационные данные сайта в коллекции `projects` и
`specialists`. Запускать последовательно и только для нужной базы. Повторный запуск
не изменяет существующие записи: проекты сопоставляются по `title`, специалисты по
`email`. Это начальное наполнение, а не синхронизация данных с фронтендом.

## API

| Метод | URL                | Ответ                                                 |
| ----- | ------------------ | ----------------------------------------------------- |
| GET   | `/api/health`      | `{ "status": "ok" }`, либо 503 при недоступности базы |
| GET   | `/api/projects`    | `[{ id, title, description, imageUrl? }]`             |
| GET   | `/api/specialists` | `[{ id, name, skill, email, portfolioUrl? }]`         |

Списки отсортированы по `sortOrder`, затем `_id`; максимум 200 записей.
В базе `sortOrder` — число, остальные поля — строки. Возвращаются только явно
разрешённые поля. При пустой коллекции ответ — `[]`.

```bash
curl http://localhost:3000/api/health
curl http://localhost:3000/api/projects
curl http://localhost:3000/api/specialists
```

## Структура

- `src/server.ts` — подключение MongoDB, HTTP-сервер, завершение работы.
- `src/app.ts` — маршруты и обработка ошибок.
- `src/config.ts` — проверка переменных окружения.
- `src/modules/content.ts` — типы документов и чтение коллекций.
- `src/seed.ts`, `src/seed-data.ts` — начальное наполнение.
- `test/api.test.mjs` — HTTP-тесты с подменой слоя базы и проверка конфигурации.

## Проверки и production-запуск

```bash
pnpm backend:test
pnpm backend:build
pnpm backend:start
```

`backend:start` использует скомпилированный `backend/dist`, а `backend:dev` —
встроенную поддержку TypeScript в Node.js 24 и перезапуск при изменении файлов.
На хостинге переменные можно задавать напрямую вместо `.env`.

Страницы «Проєкти», «Послуги» и «Звітність» загружают данные из API в браузере.
При `pnpm start` Angular проксирует `/api/**` и `/media/**` на порт 3000.
При деплое направь эти пути на API через reverse proxy того же домена.

Фото проектов хранятся в `backend/uploads/projects/` по умолчанию. Папка
создаётся при запуске API и исключена из Git. Положи туда, например,
`workshop.webp`, а в MongoDB укажи `imageUrl: "/media/projects/workshop.webp"`.
Локально файл доступен на `http://localhost:3000/media/projects/workshop.webp`.
API раздаёт JPG, PNG, WebP и AVIF. Проекты без `imageUrl` сохраняют заглушку.

На хостинге задай `PROJECT_IMAGES_DIR` абсолютным путём к постоянному диску
и проксируй `/media/projects/` на бэкенд вместе с `/api`. Храни резервные
копии файлов вместе с базой. Публичной загрузки пока нет: админка сможет
писать в эту папку через защищённый маршрут после добавления авторизации.

Портфолио специалистов хранятся в `backend/uploads/specialists/`.
Пример поля в MongoDB: `portfolioUrl: "/media/specialists/portfolio.pdf"`.
PDF открываются в браузере; DOC/DOCX, PPT/PPTX, XLS/XLSX, ODT и ZIP отдаются для скачивания.
Для деплоя задай `SPECIALIST_PORTFOLIOS_DIR` на постоянном диске и проксируй
`/media/specialists/` на API. Размещай здесь только файлы для публичного доступа.

## PDF-отчёты

Положи PDF в `backend/uploads/reports/` и добавь в коллекцию `reports` документ
`{ year: 2025, pdfUrl: "/media/reports/2025.pdf" }`.
`GET /api/reports` возвращает записи с `id`, `year` и `pdfUrl`, новые годы первыми.
На хостинге задай `REPORTS_DIR` на постоянном диске. Без записей раздел покажет пустое состояние.

## Адміністрування проєктів (перший етап)

Відкрий `/admin`. Доступний вхід, перегляд, додавання, редагування і видалення проєктів
(назва, опис, необов’язкове фото). Зміни публікуються негайно. Фото можна замінити
або прибрати; видалення проєкту потребує підтвердження. Чернетки поки не реалізовані.
Згенеровані адмінкою фото видаляються після заміни/видалення, якщо інші проєкти
їх не використовують. Файли, додані вручну, залишаються на диску. Публічної реєстрації немає.

Створи єдиного адміністратора з кореня проєкту в інтерактивному терміналі:

```bash
nvm use
pnpm admin:setup
```

Команда запитає логін і пароль (15–128 символів, прихований ввід).
Використовуй унікальний пароль із менеджера паролів. У MongoDB зберігається лише
scrypt-хеш із випадковою сіллю. Повторний запуск замінює доступ після підтвердження
і завершує всі сесії; це також локальний спосіб відновлення доступу.
Не передавай пароль через аргументи команд або Git.

Сесії зберігаються в MongoDB: 8 годин максимально, 30 хвилин бездіяльності.
Cookie має HttpOnly, SameSite=Strict, а в production також Secure і префікс
__Host-. Зміни потребують дозволеного Origin і CSRF-токена. Вхід обмежений
10 спробами за 15-хвилинне вікно для єдиного акаунта; лічильник переживає
перезапуск API. Вичерпання бюджету тимчасово блокує і правильний пароль.
Фото до 5 МБ / 25 мегапікселів декодуються та перекодовуються у WebP,
метадані видаляються; ім’я генерує сервер. SVG та анімовані фото не приймаються.

Перед production-запуском:

- Задай `NODE_ENV=production` і `ADMIN_ORIGINS=https://твій-домен` (без кінцевого `/`).
- Обслуговуй весь сайт через HTTPS; проксируй `/api` і `/media` на API того ж домену.
- Не відкривай MongoDB та порт API напряму в інтернет. Налаштуй резервні копії
  MongoDB і папки uploads та обмеження розміру запиту на reverse proxy (7 МБ).
- Не кешуй `/api/admin`. На першому етапі немає MFA; для майбутнього публічного
  запуску варто додати другий фактор.

Інтеграційні перевірки використовують окрему тимчасову базу, яку видаляють після тесту:

```bash
TEST_MONGODB_URI=mongodb://127.0.0.1:27018 pnpm backend:test
```

## Послуги та звітність в адмінці

На `/admin` є розділи «Проєкти», «Послуги» та «Звітність». Для кожного
доступні список, створення, редагування й видалення з підтвердженням.
Послуги відповідають колекції `specialists`: ім’я, опис послуг, email і
необов’язкове портфоліо. Звіти: рік 1900–2100 та обов’язковий PDF.
Адміністративні API: `/api/admin/specialists` і `/api/admin/reports` — GET/POST;
`/:id` — PUT/DELETE. Використовуються ті самі сесії, Origin та CSRF-перевірки.

Нові документи завантажуються як PDF до 10 МБ (JSON-запит до 14 МБ через base64).
Для reverse proxy збільш ліміт запиту до 14 МБ. Перевіряються розмір і сигнатура
PDF; це не антивірусна перевірка вмісту. PDF віддаються з `Content-Disposition: inline`
для перегляду в новій вкладці браузера. Портфоліо можна прибрати; звіт завжди повинен
мати PDF. Без нового файлу під час редагування зберігається попередній.
Раніше додані вручну портфоліо інших підтримуваних форматів зберігаються.
При заміні/видаленні прибираються лише створені адмінкою файли, на які немає
інших посилань у відповідній колекції.

### Фото фахівців

У розділі «Послуги» фото завантажується окремо від PDF-портфоліо:
JPG, PNG, WebP або AVIF до 5 МБ і 25 мегапікселів. Зображення перевіряється,
перекодовується у WebP без метаданих і зберігається у
`SPECIALIST_PORTFOLIOS_DIR/photos/`. Поле API — `imageUrl`, шлях до файлу —
`/media/specialists/photos/…webp`. Фото можна замінити або прибрати незалежно
від портфоліо. Без фото відображається нейтральний силует.

Адміністративний запит для послуг може містити одночасно фото та PDF,
тому ліміт JSON тут 21 МБ; відповідно налаштуй reverse proxy.
Поле `image` містить base64, `null` видаляє фото, відсутнє поле зберігає попереднє.
На публічній сторінці ім’я фахівця є посиланням для листа на його email.

## Форма «Контакти»

Форма надсилає `POST /api/contact` з іменем, email та повідомленням. Для
тестової доставки у `backend/.env` (або змінних середовища API) задай
`CONTACT_TO=buchko_olexiy@ukr.net`, `RESEND_API_KEY` та `CONTACT_FROM`.
Для тестового відправника Resend одержувач має бути адресою акаунта Resend.
Для доставки на інші адреси вкажи відправника з верифікованого домену.
Email відвідувача передається як Reply-To. Повідомлення не записується в MongoDB.

Дозволений Origin береться з `ADMIN_ORIGINS`. Публічний сайт має проксирувати
`/api/contact` на той самий Express API. Без параметрів пошти форма повертає
помилку доступності. API приймає до 10 спроб надсилання за 10 хвилин на процес.
